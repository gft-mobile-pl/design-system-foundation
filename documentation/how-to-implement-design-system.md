# How to implement Design System

Creating a design system is a complex process that requires close collaboration between the UX team and developers.
The individual steps in this process do not always follow the order presented in this document and are often repeated multiple times — due to changes in requirements, incorrect use of design tokens, or efforts to resolve inconsistencies within the system.
Nevertheless, the process of building a design system can roughly be divided into the following stages:
1. [Preparing a set of value tokens (aka reference tokens)](/documentation/how-to-implement-design-system-reference-tokens.md).
2. Defining the set of system tokens.
3. Designing components and deciding which of their properties should be stylable.

Follow the corresponding links for a detailed description of each step.

> 💡 Creating your own design system from scratch is a complex and time-consuming task.
> In most cases, a better solution is to use the [**Mobius**](https://github.com/gft-mobile-pl/mobius) library, which is based on both **Design System Foundation** and **Material Design 3**.
>
> [**Mobius**](https://github.com/gft-mobile-pl/mobius) offers a high degree of stylability and extensibility, which in most cases allows you to achieve the desired results with significantly less effort than building a custom design system from the ground up.
> Although Mobius is based on Material Design 3, it offers far greater customization through styling mechanism, which reduces the need to override the original components.
